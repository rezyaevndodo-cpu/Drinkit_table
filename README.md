# Drinkit Омск — таблица статистики

Отдельный Railway-сервис. Собирает 21 метрику по 6 точкам Drinkit + «Вся сеть», пишет в Google Sheets каждый день в 07:30 Омск.

## Метрики
Выручка · Выручка моб.приложение · Заказы · Заказы моб. · % моб. · Средний чек · Часы кухни · Производительность · Продуктивность · **KitchenCost, %** · Время на трекинге · Сервисное время · Доступность меню · Продуктов в стопе · Списания всего · % списаний · Списания (тестирование/производство/обучение/переделка/маркетинг/качество)

## Дизайн
Apple-style «Нейтральный + синий акцент»: почти белый холст, синий — точечный акцент
(верхняя полоса, шапка), у каждой из 6 точек Drinkit — свой акцентный оттенок вместо
сплошной голубой заливки. Без цветовых KPI-зон (зелёный/жёлтый/красный) — по решению
пользователя, так как пороги для Drinkit ещё не определены. Палитра задаётся константами
`T` / `UNIT_PALETTE` в начале `src/sheets.js`.

## Деплой на Railway

### 1. Новый GitHub-репозиторий
Залить все файлы (через git, чтобы папка src/ сохранилась).

### 2. Railway → New Project → Deploy from GitHub repo

### 3. Variables
| Переменная | Значение |
|---|---|
| `DODO_CLIENT_ID` | `cpmmr` |
| `DODO_CLIENT_SECRET` | `IVLoxNZFDzSkhbQHSTB5xhFpOMRvYeuB` |
| `DODO_REFRESH_TOKEN` | (бутстрап-значение — нужно только при первом запуске, дальше токен хранится в самой таблице, см. ниже) |

### 3а. Refresh-токен — durable-хранение
Dodo IS выдаёт **одноразовый** refresh_token: при каждом обновлении access_token
приходит новый refresh_token, а старый умирает. `DODO_REFRESH_TOKEN` из Railway
используется только как бутстрап при самом первом запуске — после первого успешного
обновления актуальный токен сохраняется в скрытой вкладке `_auth` этой же Google
Таблицы (см. `src/tokenStore.js`) и переживает рестарты/редеплои Railway.

Получить новый refresh_token вручную (нужно один раз — например, при первом запуске
или при добавлении нового scope):
```
node scripts/getRefreshToken.js url
```
Открыть ссылку в браузере, авторизоваться, скопировать `code` из адресной строки
после редиректа на `https://localhost:5001/?code=...`, затем:
```
node scripts/getRefreshToken.js exchange <code>
```
Вставить полученный `REFRESH_TOKEN` в переменную `DODO_REFRESH_TOKEN` в Railway.

### 4. Google Sheets
- Создать новую таблицу
- Открыть доступ service-account (тому же что у Dodo) на редактирование
- ID таблицы → в `GOOGLE_SHEET_ID`

### 5. После деплоя
- URL + `/run` — первый запуск вручную
- Листы «По дням», «По неделям», «По месяцам» заполнятся
- Дальше авто-обновление 07:30 Омск

## Особенности
- Накопление с 1 мая 2026 (как Dodo)
- Текущий незавершённый день не выводится
- «Вся сеть» — серая строка-агрегат внизу
- Доступность меню: формула по рабочему времени 07:00–22:00, MENU_SIZE=190
- Списания по writtenOffAtLocal (правильные границы дня)
- Refresh одноразовый: получил → сразу в Railway, без локальных тестов

## Недоступные метрики (нет в API Drinkit)
Часы по графику, % долгих/нормальных/идеальных, новые/старые клиенты, себестоимость, % стажёров — эндпоинтов нет.

## KitchenCost — что нужно сделать, чтобы метрика заработала
1. На developer.dodois.io включить scope `incentives` для клиента `cpmmr`.
2. Получить новый refresh_token с этим scope (см. «Refresh-токен — durable-хранение» выше) — `src/config.js` уже запрашивает `incentives` в `DODO_SCOPE`.
3. Обновить `DODO_REFRESH_TOKEN` в Railway новым токеном.
4. Запустить `GET /run` — KitchenCost посчитается за все периоды по формуле
   `ФОТ кухни / выручка × 100 × 1.62` (районный коэффициент Омск), так же как в таблице Dodo Омск.
